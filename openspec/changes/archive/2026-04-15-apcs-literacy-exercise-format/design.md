## Context

目前 1-3 到 2-4 的練習題使用兩種格式：短類題（1-2 句描述 + 提示）和基本全描述（題目說明 + I/O + 範例表）。兩者都不符合 APCS 實作題的素養式出題風格——後者以 150-400 字的情境敘事為核心，搭配精確的 I/O 規格和逐步範例說明。

此教材的目標讀者是零基礎的鳳山高中學生。直接套用 APCS 原始格式（無鷹架）會讓初學者在長題文前卡住。因此需要在 APCS 框架內嵌入教學鷹架，降低認知負荷的同時培養素養題閱讀能力。

專案已具備 Mermaid 渲染支援（`vitepress-mermaid-support` spec），流程圖可直接在 VitePress 中呈現。

## Goals / Non-Goals

**Goals:**

- 定義一個可複用的練習題格式模板，統一 1-3 到 2-4 所有練習題的呈現風格
- 建立鷹架元素的選用準則——哪種題適合數學表達、哪種適合流程圖、哪種適合拆解思路
- 確保改寫後的題目既有 APCS 素養題的閱讀份量，又不至於讓初學者無法入手

**Non-Goals:**

- 不設計新的題目（僅改寫既有題目的呈現格式）
- 不定義 challenge 檔案的格式變更
- 不涉及程式碼層面的實作（純內容改寫）

## Decisions

### 決策一：APCS 素養式格式模板結構

完整格式模板如下（每題必須包含所有帶 ✦ 標記的區塊）：

```markdown
{### 題目名稱}

<ChallengeLink slug="[slug]" />

**問題情境**：                                          ← ✦ 必要
[3-5 句敘事情境。使用具名角色（小明、阿華、老師等），
描述一個與學生生活或學科知識相關的真實場景。
情境需自然引出計算需求，而非為了出題硬套故事。
字數目標：150-300 字（中文），比照 APCS 初級題長度。]

**🔍 思考引導**：                                      ← ✦ 必要（至少選用 1 種鷹架）
[根據題目特性選用 1-3 種鷹架元素，見決策二]

**輸入格式**：                                          ← ✦ 必要
第一行：[逐行說明]（限制：[值域]）
第二行：...

**輸出格式**：                                          ← ✦ 必要
[精確描述輸出內容與格式]

**範例一**：                                            ← ✦ 必要（至少 2 組）

| 輸入 | 輸出 |
|------|------|
| `[input]` | `[output]` |

**範例說明**：                                          ← ✦ 必要
[逐步追蹤範例的計算過程，用自然語言帶學生走一次。
類似 APCS 的範例說明區塊，但語氣更親切。]

**範例二**：

| 輸入 | 輸出 |
|------|------|
| `[input]` | `[output]` |

> [!NOTE] 老師的提示                                    ← ✦ 必要
> [1-3 句策略性提示。指出關鍵觀念或常見陷阱，
> 但不洩漏完整解法。可參照教學正文的特定段落。]
```

**思考引導區塊的 Markdown 嵌套結構**：`**🔍 思考引導**：` 標題為普通粗體文字（不在 blockquote 內），各鷹架元素為獨立的 blockquote，之間以空行分隔。多鷹架範例：

```markdown
**🔍 思考引導**：

> 💭 **如果用數學來表達...**
>
> BMI 的計算公式是：
>
> $$BMI = \frac{W}{H^2}$$
>
> 其中 $W$ 是體重（公斤）、$H$ 是身高（公尺）。
>
> 那麼，怎麼把這個公式「翻譯」成 Python 呢？

> 🔀 **試著補完這張流程圖...**
>
> （Mermaid flowchart here）
```

每個鷹架元素是一個獨立的 `>` blockquote，彼此之間用空行分隔（不是嵌套 blockquote `> >`）。`**🔍 思考引導**：` 標題行本身不在 blockquote 內。

**取消 Tier 分級制**：1-3 目前使用 ★☆☆ 到 ★★★★ 的 Tier 分級。改寫後取消 Tier 標記，所有題目統一使用上述格式，按難度自然排序即可。原因：APCS 實際考試不分級，且每題自帶鷹架已能自然引導不同程度的學生。

### 決策二：鷹架元素類型與選用準則

三種鷹架元素各有適用場景，每題至少選用 1 種，至多 3 種：

#### 類型 A：數學表達（適合公式導向題）

**適用時機**：題目涉及數學公式或計算規則（BMI、判別式、計程車費、等差數列等）

**格式**：
```markdown
> 💭 **如果用數學來表達...**
>
> [題目的核心計算] 可以寫成：
>
> $$[LaTeX 公式]$$
>
> 其中 $[變數]$ 代表 [含義]...
>
> 那麼，怎麼把這個公式「翻譯」成 Python 呢？
```

**設計原則**：
- 公式使用 LaTeX 格式（專案已支援 KaTeX）
- 先給出數學表達，再引導學生思考如何轉為程式碼
- 只揭示公式本身，不揭示 Python 實作

#### 類型 B：部分流程圖（適合流程控制題）

**適用時機**：題目涉及條件判斷、迴圈流程、多步驟決策（閏年、密碼驗證、猜數字等）

**格式**：
```markdown
> 🔀 **試著補完這張流程圖...**
>
> 下面的流程圖有些步驟被 `???` 遮住了，試著想想看遮住的地方應該填什麼：
>
> ```mermaid
> flowchart TD
>     A[讀入資料] --> B{條件判斷?}
>     B -->|是| C[???]
>     B -->|否| D[另一個步驟]
>     C --> E[???]
>     D --> F[輸出結果]
> ```
```

**設計原則**：
- 使用 Mermaid `flowchart TD`（由上而下）
- 遮蔽的部分用 `???` 標示，通常遮蔽 1-3 個步驟
- 保留足夠的上下文讓學生能推理出缺失步驟
- 遮蔽位置選擇：優先遮蔽「核心邏輯步驟」而非「樣板步驟」
  - **核心邏輯步驟**：任何執行問題特定計算或做出問題特定決策的節點（條件判斷、數學運算、中間變數更新、計數器邏輯等）
  - **樣板步驟**（僅限以下兩種）：從 stdin 讀取輸入、將最終結果輸出到 stdout
  - 初始化變數、計數器遞增、迴圈變數更新等皆屬核心邏輯，可作為 `???` 遮蔽候選
- 流程圖複雜度限制：節點數不超過 8 個（含遮蔽節點）
- **注意**：Mermaid code block 放在 blockquote 內（`> ` 前綴）為此專案首次使用，需在 task 1.2 驗證渲染正確

#### 類型 C：拆解思路（適合複合型題目）

**適用時機**：題目需要多階段處理、或可分解為獨立子問題（日期驗證、找零、巢狀迴圈圖形等）

**格式**：
```markdown
> 🧩 **把大問題拆成小問題...**
>
> 這題乍看很複雜，但可以分成幾個步驟：
>
> 1. **第一步 — [子問題名稱]**：[簡短描述]
> 2. **第二步 — [子問題名稱]**：[簡短描述]
> 3. **第三步 — ???**：你覺得接下來要做什麼？
>
> 每個步驟單獨來看都不難，難的是把它們串起來！
```

**設計原則**：
- 列出 3-5 個步驟
- 最後 1-2 步可以用 `???` 遮蔽，讓學生自行推理
- 每步描述用一句話，不寫程式碼
- 步驟應對應程式中可識別的區塊（如一個迴圈、一個 if-else）

### 決策三：各節鷹架選用對照表

根據各節教學主題與題目特性，建議的鷹架選用如下：

| 節次 | 教學主題 | 主要鷹架 | 次要鷹架 | 理由 |
|------|---------|---------|---------|------|
| 1-3 | if-elif-else | B 流程圖 | A 數學（公式題）、C 拆解（複合題） | 條件判斷最適合用流程圖視覺化 |
| 1-4 | 模組一總結 | C 拆解 | A 數學 | 綜合題需拆解引導 |
| 2-1 | for 迴圈 | A 數學 | B 流程圖 | 數列/累加公式 + 迴圈流程 |
| 2-2 | while 迴圈 | B 流程圖 | A 數學、C 拆解 | 不確定次數的迴圈最適合流程圖 |
| 2-3 | break/continue | B 流程圖 | C 拆解 | 迴圈控制流程的視覺化 |
| 2-4 | 巢狀迴圈 | C 拆解 | B 流程圖 | 複雜圖形需拆成外圈/內圈子問題 |

### 決策四：問題情境敘事風格

**角色命名**：使用常見中文名（小明、阿華、小芳等），每題角色不重複以避免混淆。每個角色需有一個可辨識的身份或情境（如「便利商店打工的小華」、「數學課上的阿翔」）。

**情境類型優先序**：
1. 學生日常生活（校園、社團、考試、打工）
2. 數學/自然課堂連結（呼應高中學科知識）
3. 遊戲/娛樂場景（比照 APCS「遊戲選角」風格）

**語氣**：比 APCS 正式題目稍微輕鬆，保持教材的親切感。可使用括號補充說明或顏文字，但不過度。

### 決策五：範例說明撰寫規範

範例說明需逐步追蹤計算過程，格式如下：

```
以範例一為例：輸入 N = 48, M = 18。
第一步：48 ÷ 18 = 2 餘 12，所以 a = 18, b = 12
第二步：18 ÷ 12 = 1 餘 6，所以 a = 12, b = 6
第三步：12 ÷ 6 = 2 餘 0，所以 a = 6, b = 0
b 變成 0 了，迴圈結束，答案是 a = 6。
```

- 使用「第 N 步」標記每一步
- 每步寫出具體數字的計算過程
- 最後一步明確標示結論
- 語氣自然，可加入引導性問句（「看到規律了嗎？」）

## Risks / Trade-offs

**[風險] 題目敘述過長導致學生放棄閱讀** → 透過鷹架元素提供視覺錨點（公式框、流程圖、編號步驟），打破長段文字的壓迫感。每題的問題情境控制在 150-300 字。

**[風險] 鷹架元素給太多提示，學生不需思考** → 流程圖遮蔽關鍵步驟、拆解思路隱藏最後步驟、數學公式只給公式不給程式碼，確保學生仍需完成「最後一哩」的翻譯工作。

**[風險] 改寫工作量龐大（~40 題）** → 按節次分批實作，每節為獨立 task，可平行進行。先完成格式模板 spec 確保一致性。

**[取捨] 取消 Tier 分級** → 失去難度分層的視覺提示，但換來格式統一和 APCS 風格一致性。學生仍可從鷹架元素的多寡感受難度梯度（簡單題用 1 種鷹架，複雜題用 2-3 種）。
