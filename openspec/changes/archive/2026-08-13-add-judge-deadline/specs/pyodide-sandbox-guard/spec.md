## MODIFIED Requirements

### Requirement: Sandbox guard is injected before user code in every execution

The sandbox guard code SHALL be part of the wrapped Python code generated by `buildWrappedCode()`. It SHALL execute before the user's code. When an op limit applies (`opLimit` is a number), the guard SHALL execute after the `sys.settrace` op-counter setup; in exempt mode (`opLimit: null`, trusted generator code) the op-counter setup is intentionally absent and the sandbox guard SHALL be the first injected block.

The wrapped code SHALL be executed synchronously. It SHALL NOT be executed through the Pyodide asynchronous entry point, because an interrupt raised during asynchronous execution surfaces outside the caller's exception handling and terminates the Worker instead of producing a verdict.

#### Scenario: Guard executes in correct order

- **WHEN** `buildWrappedCode()` generates the full Python script with a numeric `opLimit`
- **THEN** the execution order SHALL be: (1) op-counter setup, (2) sandbox guard, (3) stdin/stdout redirect, (4) user code

#### Scenario: Exempt mode keeps guard-first order

- **WHEN** `opLimit` is `null`
- **THEN** the execution order SHALL be: (1) sandbox guard, (2) stdin/stdout redirect, (3) user code — with no op-counter setup present

#### Scenario: Wrapped code runs synchronously

- **WHEN** any of the `run`, `run_only`, or `execute` handlers executes wrapped student code
- **THEN** it SHALL use the synchronous Pyodide execution entry point
- **AND** an interrupt raised while that code runs SHALL be catchable by the handler and classifiable as a timeout
