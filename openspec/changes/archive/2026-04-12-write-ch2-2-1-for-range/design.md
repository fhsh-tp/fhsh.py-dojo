## Context

模組一（Ch1）已完成 4 節教學內容（1-1 至 1-4），學生已學會：`print()`、`input()`、變數、資料型別（int/float/str）、型別轉換、四則運算、布林值、比較/邏輯運算子、`if-elif-else` 流程控制。

2-1 是模組二的起始節。迴圈是零基礎學生遭遇的第一個真正抽象概念——不像 `if-else` 可以用日常決策直覺理解，「讓電腦重複做某件事 N 次」需要建立全新的心智模型。這是 CS1 課程中公認的 drop-off point，教學設計必須格外細緻。

**約束條件：**
- 目標讀者：高一零基礎學生，自學環境（無老師即時指導）
- 撰寫規則：Ch1 的 12 條通用編輯規則（P-1 至 K-1）全數適用
- T-1 限制：`list`、`dict`、`while`、`break`、`continue` 皆尚未教授，不可正式使用
- 1-4 的模組二預告已用「100 行 input vs 3 行迴圈」做了 hook 鋪陳

## Goals / Non-Goals

**Goals：**

- 讓學生理解「為什麼需要迴圈」（從重複勞動的痛苦出發）
- 教會 `for i in range(n)` 基礎計數迴圈
- 教會 `range(start, stop, step)` 三參數用法
- 每個知識節點配 1 例題完整 walkthrough + 2 類題（hint only）
- 遵循全部 12 條撰寫規則

**Non-Goals：**

- 不教 `while`（2-2 範圍）
- 不教 `break`/`continue`（2-3 範圍）
- 不教 `for item in list` 迭代（2-4 範圍）
- 不教巢狀迴圈（nested loop，2-5 範圍）
- 不產生實際圖片檔案

## Decisions

### 開場 Hook：從 1-4 預告接棒

從 1-4 結尾的「100 行 input vs 3 行迴圈」荒謬對比直接接棒。2-1 開頭不重新破題，而是回應 1-4 留下的懸念：「上一節結尾，我們看到了一個人寫了 100 行 input 被嘲笑的場景。今天，你就是那個拿咖啡悠哉的人。」

**理由**：避免每節都從零開始建立動機，利用已有的情緒鋪陳（學生在 1-4 已經對迴圈產生好奇），直接進入教學。

### 生活比喻策略：「罰寫」比喻

用「老師罰你抄寫 100 遍」作為 for 迴圈的核心比喻。

- 「罰寫 100 遍」= `for i in range(100)`
- 「從第 3 遍開始寫到第 10 遍」= `range(3, 10)`
- 「每隔 2 遍抄一次」= `range(0, 100, 2)`

**理由**：高中生對「罰寫」有強烈的共感經驗。比喻能自然延伸到 range 的三個參數，不需要切換比喻。符合 S-1 規則（比喻前需 meta-cognitive bridge）。

**替代方案考量**：考慮過「跑操場圈數」比喻，但 range 的 start/stop/step 不容易對應到跑步場景。

### 心智模型追蹤：Trace Table 格式

每個 for 迴圈範例都附帶一個 Trace Table（追蹤表），逐步展開 `i` 的值與每次迴圈的輸出。格式：

```
| 第幾次 | i 的值 | 執行內容 | 輸出 |
|--------|--------|---------|------|
| 1      | 0      | print(0)| 0    |
| 2      | 1      | print(1)| 1    |
| ...    | ...    | ...     | ...  |
```

**理由**：M-1 規則要求 compound expression 附帶 step-by-step trace。迴圈的「重複」是隱性的（程式碼只寫一次，但執行多次），用表格讓每次迴圈的狀態可見化，是建立迴圈心智模型的關鍵手段。

### T-1 前引用處理

2-1 在講「為什麼需要迴圈」時，不可避免地會暗示「未來有更好的方式處理多筆資料」。處理方式：

- **禁止**直接使用「串列」、「list」
- **允許**用白話描述：「一整排資料」、「一堆資料」
- 若必須預告，使用 controlled forward reference：「（後面幾節會教一個叫做『串列』的工具，專門用來整理大量資料）」

### 知識節點拆分與例題配置

**知識節點 A：`for i in range(n)` 基礎計數迴圈**
- 教學重點：for 語法結構、range(n) 產生 0 到 n-1 的序列、縮排（indentation）的意義
- 例題（ID 11）：需設計一道純計數迴圈題，例如「累加器」（讀入 N，印出 1+2+...+N 的結果）
- 類題 1（ID 12）：簡單重複輸出題
- 類題 2（ID 13）：累加/累乘變形題

**知識節點 B：`range(start, stop, step)` 進階用法**
- 教學重點：range 的三參數、負步長（倒數）、常見 off-by-one 錯誤
- 例題（ID 14）：需設計一道需要 start/stop/step 的題目，例如「倒數計時器」（讀入 N，從 N 印到 1）
- 類題 1（ID 15）：奇數/偶數序列題
- 類題 2（ID 16）：區間操作題

**理由**：遵循 S-3 規則（H2 過渡需 2-4 句），每個 H2 段落內含教學 + 例題 + 練習的完整循環。例題位置遵循 1-1/1-2 的模式：先教概念，再用 Judge 例題做完整 walkthrough，最後附類題。

### 錯誤預防策略（E-1 合規）

每個知識節點教完語法後，立即警告最常見的錯誤：

- `for i in range(n)`：忘記冒號、縮排錯誤（IndentationError）、`range(5)` 不包含 5
- `range(start, stop, step)`：off-by-one（「為什麼 `range(1, 5)` 只到 4？」）、step 為 0 的 ValueError

## Risks / Trade-offs

- **[風險] 2-1 篇幅過長** → 兩個知識節點各含教學 + trace table + 例題 + 2 類題，可能超過 400 行。緩解：嚴控每個 H3 小節長度，trace table 行數限制在 5 行以內（用 `...` 省略中間步驟）
- **[風險] range 的 off-by-one 讓學生挫折** → 在 E-1 錯誤預防區塊用強烈的視覺提示（WARNING container）標注，並用「數手指」的比喻解釋「從 0 開始數」和「不包含結尾」
- **[風險] 缺乏 list 導致範例受限** → for 迴圈只能搭配 range() 使用數字序列，無法展示「遍歷一串名字」等生活化場景。緩解：在動機段落用白話描述未來會有更強大的工具，配合 T-1 controlled forward reference
