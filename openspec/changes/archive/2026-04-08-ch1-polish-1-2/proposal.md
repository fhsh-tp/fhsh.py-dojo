## Why

`1-2.md`（變數、數字與文字）是學生第一次接觸變數、型別、運算的章節。經 `ch1-polish-1-1` 建立的 8 條編輯規則審視後，發現存在與 1-1 相同的系統性問題：破折號過度使用、部分 code block 缺乏對話式 lead-in、`int(input())` 求值模型未顯性解釋、段落過場密度不均。

此變更獨立於 1-1 的修改，但參照同一套編輯規則，確保兩節的教學體驗一致。

完整編輯規則定義見 `openspec/ch1-editorial-review.md` 第 3 節。

## What Changes

### P-1 標點風格統一

逐行審計 `——` 的使用。對「例行性子句銜接」改為逗號或冒號，保留 hook/笑話中的正當戲劇效果用法。

### C-1 Code block 對話式 lead-in

檢查以下 code block 是否有 1~2 句過場：
- 變數宣告 `name = "小明"`
- 等號指派 `x = 5` / `x = 10`
- `type()` 示範
- `input()` 型別陷阱 `a + b = "12"`
- `int(input())` 轉換示範
- 四則運算各段
- 整數除法 `//` 與取餘數 `%` 生活比喻後的 code block
- 收銀機解題的 code block

### M-1 求值模型顯性化

`int(input())` 是 1-2 的核心組合技。需確認是否有顯性的 step-by-step trace 說明求值順序（先 `input()` → 得到字串 → 再 `int()` 轉換），並 callback 到 1-1 的 `print(1+1)` 求值模型。

### S-1 類比 meta-cognitive bridge

「置物櫃比喻」前是否有一句「為什麼要用這個比喻」的鋪陳。若無，補上。

### S-3 段落過場密度

檢查以下段落邊界的過場是否足夠（2~4 句）：
- 「變數」→「資料型別」（L99 `好，你會貼標籤了。但標籤上的東西，有分「種類」的⋯⋯`）
- 「資料型別」→「四則運算」（L182 `型別搞懂了？來看看數字能玩什麼花樣。`）
- 「四則運算」→「Judge 解題實戰」（L249 `好，武器都齊了。來實戰看看！`）

### T-1 術語前向引用審計

掃描全檔，確認是否有使用尚未教過的術語（如 1-3 的 `if`、`bool` 等）。已知 `f"{result:.1f}"` 在 L323 為受控前向引用（標註「偷學一招」），不需修改。

### S-2 笑話後語氣銜接

掃描所有 kaomoji / 括號笑話後的下一句，確認有 callback connector。

### E-1 錯誤預防

檢查是否有常見初學者陷阱在引入語法時即說明，而非僅在「常見錯誤」區塊提及。重點關注：
- `int()` 轉換時輸入非數字的情況（L178 已有說明，確認語氣充分）
- 字串 `*` 整數的行為（L303 已提及，確認解釋清楚）
