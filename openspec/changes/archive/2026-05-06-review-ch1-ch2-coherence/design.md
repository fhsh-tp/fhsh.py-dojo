## Context

復興高中 Python 自學 Judge 平台（fhsh.py-dojo）目前已上線 Ch1（與電腦溝通的基礎）與 Ch2（迴圈與重複結構），讀者為高一完全零基礎、自學的學生。經跨章節審核發現：

1. **Ch2 有 4 處概念在介紹前就被使用**：
   - 字串乘法 `"*" * n` 出現於 2-1（星星正方形類題提示）與 2-4（巢狀迴圈正文與多個提示），但全課程從未正式介紹字串能與整數相乘。
   - `\t` 跳脫字元出現於 2-4 九九乘法表的 Judge 解答，但跳脫字元概念未在前序章節介紹。
   - `f-string` 格式化（`f"{i*j:4}"`）同樣出現於 2-4 九九乘法表 Judge 解答；雖然 1-2 預告「後面才會學」，但實際上從未正式教過。
   - 序列展開 `print(*range(...))`（unpacking operator）出現於 2-4 數字金字塔的提示，遠超目前章節範疇。

2. **Range 說明有 4 處可改善**：
   - 「為什麼包頭不包尾」現況以「用久了你會發現這個設計其實很方便（後面會解釋為什麼）」帶過，但全章從未真的解釋。研究 Edsger W. Dijkstra 1982 年的手稿〈Why Numbering Should Start at Zero〉與多篇 Python 教學文獻後，發現有三個經典理由可以提供（長度好算、空集合自然、可乾淨切分）。
   - 「省略鏈」說法將 `range(5)` 描述為「`range(0, 5, 1)` 的省略」，但 `range` 在 CPython 是有多個建構式簽名的類別，不是預設參數機制。對學生不算錯誤，但可以改寫為更誠實的「三種便利寫法對應三種場景」。
   - 沒有提到 `range` 不是 list — 學生若試 `print(range(5))` 會看到 `range(0, 5)` 而非 `0 1 2 3 4`，這是常見的初學困惑。
   - 通篇「步長/公差」用語混雜（「每次加」「每次跳」「每次減」「每次增加」「每隔」交錯），其中**「每隔 2 遍寫一次」是錯誤描述**：`range(0, 10, 2)` 是「每次加 2」（產生 0, 2, 4, 6, 8），不是「每隔 2 遍」（那會是 1, 4, 7, 10）。

3. **本專案約束**：
   - 撰寫一律用台灣慣用繁體中文，嚴禁中國大陸用語。
   - Phoenix 偏好極度詳細、step-by-step 的教學風格（適合零基礎自學）。
   - 已使用 Spectra（SDD）工作流管理開發，本 change 必須符合 `audit: true` 的稽核要求。

## Goals / Non-Goals

**Goals:**

- 修正 Ch2 全部 4 處概念提前出現問題，讓所有出現的語法/概念都在使用前已被介紹。
- 重寫 Ch2-1 的 Range 說明，使其在「為什麼」「術語精確度」「概念完整性」「用語一致性」上達到「可教學」的嚴謹度。
- 每個 Phase 完成後強制執行 `/spectra-audit` 稽核閘門（連貫性、技術正確性、用語與教學品質三個 sub-agent），確保品質。
- 全程台灣繁中、避免大陸用語。

**Non-Goals:**

- 不重寫 Ch1-1、Ch1-3、Ch1-4、Ch2-2、Ch2-3、Ch2-5（這些章節經審核連貫性良好）。
- 不更動 Judge 題目本身（題目情境、輸入輸出格式、測試資料皆不動）。
- 不改變章節順序、不開新章節。
- 不變更「罰寫」比喻（高中生有共鳴、敘事清楚）。
- 不移除 1-2 對 f-string 的「後面才會學」預告（合法的伏筆）。
- 不引入 `Decimal`、`from __future__ import` 等與當前範疇無關的 Python 進階特性。

## Decisions

### Decision 1: 在 1-2 正式介紹字串運算（`+`、`*`），而非在 Ch2 個別補充

**選擇**：在 `docs/tutor/py/ch1/1-2.md` 的「資料型別：數字跟文字不一樣」段落新增「字串也能做運算」小節。

**理由**：
- 字串是 1-2 的核心教學主題之一，補在這裡最符合教學連貫性。
- 一次性處理可避免 Ch2-1、Ch2-4 多處要補同樣的內容。
- 與 Phoenix「越詳細越好」的偏好一致。

**替代方案**：
- A：在 Ch2-1/Ch2-4 個別補小知識區塊 — 缺點是分散、無法統一管理。
- B：完全避免字串乘法、改用雙重迴圈 — 缺點是丟失 Pythonic 風格、且 Ch2-4 的「等腰三角形」用字串乘法寫法更直觀。

### Decision 2: 在 2-4 內補 `\t` 與 `f-string` 的 inline NOTE，而非在 Ch1 加新節

**選擇**：在 `docs/tutor/py/ch2/2-4.md` 的「九九乘法表」程式碼之前新增 NOTE 區塊，分別介紹 `\t` 與 `f-string`。

**理由**：
- 這兩個語法只在九九乘法表用一次（Ch2 範圍內），用 inline NOTE 是最小變動。
- 不需在 Ch1 提前介紹「對齊輸出」這種較進階的話題（會打亂 Ch1 節奏）。
- f-string 在 1-2 已有預告，2-4 才正式講解符合「先預告後正式教」的學習曲線。

**替代方案**：
- A：在 Ch1 新增「輸出格式」一節 — 缺點是動章節結構太大。
- B：避免使用 `\t` 與 `f-string`、改用簡單空格分隔 — 缺點是九九乘法表會排不齊（兩位數的 `72` 跟一位數的 `9` 對不齊），失去視覺示範意義。

### Decision 3: 移除 `print(*range(...))` 提示、保留字串乘法提示

**選擇**：
- 數字金字塔提示中移除 `print(*range(1, i+1))` 的 unpacking 寫法，只保留 `if j < i` 加空格的解法。
- 等腰三角形提示中保留字串乘法寫法（因為 Decision 1 已正式介紹）。

**理由**：
- Unpacking operator 是 Ch3 之後才該講的進階概念，連 list 都還沒教。
- 字串乘法經 Decision 1 鋪陳，可以放心用。

### Decision 4: Range 說明採「保留架構、針對性補強」策略

**選擇**：不打掉重練，針對 4 個具體問題點補強：
- 補 Dijkstra 三理由（長度好算、空集合自然、可乾淨切分）。
- 重寫「省略鏈」為「三種便利寫法對應三種場景」。
- 補 NOTE「range 不是 list，可以用 list(range(5)) 看內容」。
- 統一通篇用語為「每次加 N」「每次減 N」，特別修正錯誤描述「每隔 2 遍寫一次」。

**理由**：
- 既有「罰寫機」比喻、Trace Table、等差數列彩蛋這些優點都該保留。
- 增量修正比重寫風險低，也符合「最小變動實現最大連貫性提升」的原則。

### Decision 5: 用 Dijkstra 1982 論述背書「為什麼包頭不包尾」

**選擇**：在 2-1「常見錯誤：差一錯誤」附近補充 NOTE，列出三個 Dijkstra 提出的理由，但用台灣高中生能懂的語言改寫。

**理由**：
- 不直接引用學術文獻（學生看不懂），但用「長度好算、空集合自然、可乾淨切分」三句白話說明設計理由。
- 把「Python 設計決定」從「規定就是這樣」變成「有原因的設計」，符合零基礎學生「凡事問為什麼」的學習特質。
- 為 Ch3 之後的演算法（特別是 array 切片、二分搜尋）鋪路。

### Decision 6: 每階段強制 `/spectra-audit` 三 sub-agent 稽核

**選擇**：tasks.md 的每一個 task 結尾都明確標註「執行 `/spectra-audit` 三 sub-agent 稽核」收尾步驟。

**理由**：
- 使用者明確要求每階段完成後執行 `/spectra-audit`。
- 稽核三個維度：連貫性（不引入新破洞）、技術正確性（程式可執行、說明正確）、用語與教學品質（台灣繁中 + 風格一致 + 詳細度足夠）。
- 防止「修一個壞一個」的回歸問題。

## Risks / Trade-offs

- **風險：1-2 加新小節會增加章節長度，影響閱讀節奏** → 緩解：把「字串運算」放在「三種基礎型別」之後、「`input()` 的型別陷阱」之前，讓型別教學連續完整再進入運算；範例簡短（每個運算 2-3 行範例）。

- **風險：Range 重寫可能改變既有學生用過的範例代碼，造成混淆** → 緩解：所有程式範例本身（如 `for i in range(5):` `for i in range(1, n + 1):`）都不變，只改說明文字與用語。

- **風險：Dijkstra 三理由太抽象，高中生看不懂** → 緩解：用「長度好算 = 7 - 1 = 6 直接相減」「空集合自然 = range(5,5) 就是空」「可乾淨切分 = range(0,5) + range(5,10) 不重不漏」三句具體例子說明，配合 NOTE 區塊呈現，不強迫一定要懂全部。

- **風險：每階段 `/spectra-audit` 增加實作時間** → 接受：使用者明確選擇此模式，品質優先於速度；且每個 audit 是並行三個 sub-agent，不會 3x 慢。

- **取捨：保留「罰寫」比喻 vs 換成「中性」比喻** → 保留。理由：高中生對罰寫有共鳴、敘事清楚有趣，且使用者已明確選擇保留。

- **取捨：為 ch2-cross-chapter-audit spec 新增的「字串運算/跳脫字元/f-string 連貫性檢查」可能被未來新章節再度突破** → 接受：spec 增補後會有明確的檢查清單，後續章節若使用這些概念可主動引用，不影響既有設計。
