## Context

`docs/challenge/` 底下 71 道題目頁的內文各自演化，數學陳述累積出四種寫法：Unicode 記號（`1 ≤ n ≤ 1500`）、ASCII 拼寫（`1 <= n <= 1000`）、包在反引號裡的約束（`` `T >= 1` ``）、以及 LaTeX（只有 3 題）。站台的 MathJax 從 2026-04 就開著，教學文章一直在用，題目頁沒跟上。

apcs013／apcs014 的試點（commit `4fc1a87`）確立了寫法，本 change 把它推到其餘 53 題並補上守門。

三個必須先講清楚的既有事實：

- **pool hash 只吃 frontmatter 的 `params` 與 `testcase_plan`**，內文改動不觸發測資池或 WASM 重建。這是本 change 能純改內文的前提。
- **Tailwind preflight 的 `svg { display: block }` 會把每個行內公式推到獨立一行**。修正（`mjx-container > svg { display: inline; }`）已在本分支 commit `29e381c` 落地，但沒有 spec 也沒有回歸測試。53 頁的可讀性完全押在這一條 CSS 上。
- **題目頁用 Tailwind Typography 的 `prose` 樣式**，教學文章用 VitePress 的 `vp-doc`。兩者的行內 `<code>` 呈現不同（`prose` 會多顯示一對反引號），所以「反引號 vs LaTeX」的選擇在題目頁比在教學文章更有感。

## Goals / Non-Goals

**Goals:**

- 53 道題目頁的數學陳述改用 LaTeX，與已完成的 3 題一致。
- 建立一張**記號分類表**當單一真相來源，讓「這段該不該轉」有唯一答案，不必逐題重新判斷。
- 把分類表變成 `pnpm test` 會失敗的機械守門，讓新題目無法漂移回舊寫法。
- 把規則寫進 `Usage.md`，讓出題者在寫題目時就看得到，而不是等 CI 打回來。
- 補上行內公式渲染的 spec 與回歸驗證，讓 `29e381c` 的修正不會在未來被 Tailwind 升級默默吃掉。

**Non-Goals:**

- **不改 frontmatter**。一個欄位都不動。
- **不改 `docs/tutor/` 的教學文章**。那些頁面已在用 LaTeX，且樣式基底不同。
- **不修 `prose` 的 `code::before/after` 反引號問題**。使用者 2026-08-16 明確表示不修，這是本 change 最容易被順手改掉的東西。
- **不動波浪號範圍**（`1~9`、`3 ~ 90`）。理由見下方決策。
- **不動範例輸入／輸出區塊與 code fence 內容**。那些是字面資料。
- **不把純散文數字 LaTeX 化**。「模式 1」維持「模式 1」。

## Decisions

### 記號分類表：什麼進 LaTeX、什麼留反引號、什麼不動

這張表是本 change 的單一真相來源。轉換與審查都只依這張表，不另立判斷。

| 語境 | 判準 | 寫法 | 實例（現況 → 目標） |
| :--- | :--- | :--- | :--- |
| 不等式／約束 | 陳述一個量的範圍 | LaTeX | `1 ≤ T ≤ 3` → `$1 \le T \le 3$` |
| 反引號包住的約束 | 同上，只是被誤包在反引號裡 | LaTeX | `` `1 <= n <= 1000` `` → `$1 \le n \le 1000$` |
| 算式 | 含運算子的式子 | LaTeX | `N×(N−1)×…×(N−M+1)` → `$N \times (N-1) \times \cdots \times (N-M+1)$` |
| 賦值陳述 | 「某變數等於某值」 | LaTeX | `以 N=10、M=2 為例` → `以 $N = 10$、$M = 2$ 為例` |
| 指數 | 上標 | LaTeX | `2^(D−1)` → `$2^{D-1}$`；`身高(m)²` → `身高(m)$^2$` |
| 大數 | 位數多到要數零 | LaTeX | `1000000000` → `$10^9$` |
| 帶號數值 | 表格或行文中的負數 | LaTeX | `−2` → `$-2$` |
| 散文中的變數字母 | 單一拉丁字母代表題目中的一個量 | LaTeX | `` 輸出 `n` 行 `` → `輸出 $n$ 行`；`整數 T，代表輪數` → `整數 $T$，代表輪數` |
| 輸入行格式 | 字面上一整行會長什麼樣 | 反引號 | `` `D I` ``、`` `M n` ``（維持） |
| 輸出字串 | 程式要印出的字面字串 | 反引號 | `` `Two Real Roots` ``（維持） |
| 字面圖形 | 在範例圖表中代表某個符號本身 | 反引號 | 甘特圖裡的 `` `·` ``（維持） |
| 純散文數字 | 不是變數、不是式子的一部分 | 不動 | 「模式 1」、「去掉尾端的 0 得到 9」 |
| 波浪號範圍 | 中文排版的區間寫法 | 不動 | `1~9`、`3 ~ 90` |
| 圖片 alt | 不經 Markdown 渲染 | 不動 | `![📷 **圖 1**：`D = 4` 機台…](…)` |
| code fence 內容 | 字面資料 | 不動 | 範例輸入／輸出 |

判斷順序：**先問「這串字元會不會原封不動出現在輸入或輸出裡」**——會，就是反引號；不會，再問「它是不是一個數學陳述」——是，就是 LaTeX；都不是，不動。

考慮過但否決的替代做法：只轉不等式、其餘不動。這樣做同一頁裡 `$1 \le n \le 1000$` 和 `n×n` 並存，字型不一致反而比全部不轉更難讀。

### 散文中的變數字母也進 LaTeX

apcs014 的試點已經這樣做（`第 $I$ 顆`、`整數 $T$`），這裡沿用。代價是高密度題目（`prize-order-code` 有 `N`／`M`／`T` 遍布全文）的 diff 會比只轉不等式大得多。

接受這個代價的理由：不等式裡的 `$n$` 與散文裡的 `n` 若字型不同，讀者要多花一次認知去確認「這兩個是同一個東西」。混排的成本由每一位讀者付，統一的成本只付一次。

### 波浪號範圍與純散文數字維持原樣

`1~9`、`3 ~ 90` 是中文排版的區間寫法，不是數學記號。改寫成不等式需要一個變數名，而這些位置常常沒有變數名（例如「一個 1~9 的數字」）。硬轉會逼出臨時變數，讓句子變難讀。

純散文數字同理：`去掉尾端的 0 得到 9` 裡的 `0` 和 `9` 是敘述中的數字，不是式子的一部分。我在試點時把「模式 1」轉成「模式 $1$」，那是過度轉換，已回退。

### 中文與公式混排時只包住數學片段

MathJax 對 CJK 的字距與字重處理不佳，`\text{體重}` 出來的字重與內文不同。所以不把中文塞進 `$…$`：

- 否決：`$\text{BMI} = \dfrac{\text{體重}}{\text{身高}^2}$`
- 採用：`BMI = 體重(kg) / 身高(m)$^2$`

代價是同一個公式被切成中文與 LaTeX 兩段，語意上不如整段公式漂亮；但呈現一致性優先。

### 貨幣符號一律 escape 成反斜線加錢字號

`movie-ticket.md` 的票價寫成 `$150`、`$250`、`$350`、`$50`，內文共 5 個裸錢字號。目前僥倖沒被 MathJax 吃掉——每個錢字號前面都是空白或表格分隔線，不是合法的結束定界符——但該頁本身要新增 `$\ge 65$`，同頁混用兩種語意的錢字號是已知地雷。

一律 escape。守門測試會擋下未 escape 的裸錢字號，所以未來新題目寫價格時會被 CI 提醒。

### 兩級記號黑名單與 lint 逃生門

守門測試把記號分成兩級，因為 `print-farm-schedule.md` 的甘特圖說明有一個字面的 `` `·` ``，一刀切會誤殺：

- **A 級（連反引號內都禁止）**：`≤`、`≥`、`＜`、`＞`、`<=`、`>=`。這些在題目頁只可能是約束陳述，`` `T >= 1` `` 這種誤包正是要抓的目標。
- **B 級（僅散文禁止，反引號內允許）**：`×`、`−`、`·`、`≠`、`≈`、`⌊`、`⌋`、`⌈`、`⌉`、`√`、`∑`、`∞`、`²`、`³`、`⁴`、`ⁿ`。這些可能是字面圖形。

逃生門：某一行前面加上 HTML 註解形式的 `latex-lint-ignore-next-line` 標記，該行跳過檢查。將來若真有題目要在散文中引用含比較運算子的 Python 片段，用這個標記，並且該標記本身在 diff 裡看得見、審查得到。

掃描面的計算順序固定為：取 frontmatter 之後的內文 → 去掉 code fence → 去掉圖片語法 → 去掉配對成功的 `$…$` 與 `$$…$$` → 剩下的才檢查。順序寫進測試的註解，因為順序錯了（例如先去 `$…$` 再去 code fence）會產生假陽性。

### 守門測試放在 vitest 而非獨立腳本

`scripts/trace-lint.py` 是獨立執行的 Python 腳本，沒接進 CI，要靠人記得跑。本 change 的守門要擋的是**未來新題目的漂移**，沒接 CI 就等於沒有。所以寫成 `scripts/latex-notation.test.ts`，跟著 `pnpm test` 跑，與 `scripts/challenge-params.test.ts` 同一個模式：讀 `docs/challenge/*.md`、逐題斷言、失敗訊息指名是哪一題哪一個記號。

失敗訊息必須包含檔名、行號、以及踩到的記號本身。只說「有 3 題不合規」會逼下一個人重新寫一次掃描器。

考慮過用 Python 寫（與 `trace-lint.py` 一致），否決的理由就是接不進 `pnpm test`。

### 規則表獨立成 JSON，兩個讀取端各自實作掃描

實作階段補上的決策。原本的安排是守門測試（TypeScript）與盤點腳本（Python）各自持有一份黑名單，那會讓兩份清單無聲地漂移。

考慮過讓守門測試直接 spawn `scripts/latex-notation-survey.py --json`，只留一份實作。**否決**：`scripts/content-regression.test.ts` 在環境沒有 python3 時會 `skip` 自己，守門測試若走同一條路就繼承了一條靜默通過的路徑，而「不能靜默通過」正是這個守門存在的全部理由。

採用的做法是把規則抽成 `scripts/latex-notation-rules.json`（`tierA`、`tierB`、`ignoreMarker` 三個鍵），兩端各自實作掃描但共讀這一份。掃描邏輯重複兩次是已知代價；換來的是守門測試零外部相依，且規則本身只有一處可改。兩端的掃描面計算順序相同，且各自帶負向控制，任一端漂掉都會在自己的自我檢查裡先炸開。

### 分頁批次順序：由高密度到低密度

53 題分成四批執行，依符號密度由高到低。高密度題目的判斷難度也高（`prize-order-code` 有算式、大數、變數、範例說明），先做它們可以在還有餘裕時把分類表的漏洞逼出來；低密度題目多半只有兩個 `≤`，是機械替換。

反過來做（先做簡單的）會在最後才發現分類表不夠用，那時前面 40 幾題已經照舊表改完了。

### 行內公式渲染的回歸驗證

`29e381c` 的 CSS 修正沒有測試。回歸的症狀很具體：**一個含 N 個行內公式的段落，高度會從 1 行變成 N+1 行**。所以驗證方式是量段落高度，不是量 CSS 字串。

在瀏覽器對已轉換的頁面取一個含多個行內公式的段落，斷言其 `offsetHeight` 小於「行高乘以公式數量」。同時取一個 `mjx-container > svg` 斷言其 computed `display` 為 `inline`。兩者一起記進證物檔。

用 jsdom 做不到——jsdom 不做版面計算，`offsetHeight` 恆為 0。所以這一項是瀏覽器驗證，記進 change 的證物檔，不進 vitest。

## Implementation Contract

**Behavior**

- 讀者在 53 道題目頁看到的數學陳述以 MathJax 排版呈現，與 apcs013／apcs014 一致；行內公式與同段落前後文排在同一行。
- 出題者在 `Usage.md` 的「Markdown 內文結構」章節讀得到記號分類表。
- 開發者執行 `pnpm test` 時，任何違反 A 級或 B 級黑名單的題目頁會讓測試失敗，訊息指名檔名、行號與記號。

**Interface / data shape**

- 守門測試：`scripts/latex-notation.test.ts`，vitest 檔案，無對外介面，斷言失敗時輸出形如 `docs/challenge/<slug>.md:<line> 出現 A 級記號 "<="，請改寫成 LaTeX（見 Usage.md 記號分類表）` 的訊息。
- 逃生門標記：HTML 註解，內容為 `latex-lint-ignore-next-line`，作用範圍是緊接的下一行。
- 盤點腳本：`scripts/latex-notation-survey.py`，接受一個選填的 `--json` 旗標。不帶旗標時輸出人可讀的分級清單；帶旗標時輸出物件，鍵包含 `total`、`converted`、`pending`、`clean`、`per_file`，其中 `per_file` 是以檔名為鍵、值為含 `symbols`、`detail`、`latex`、`bare_dollar` 四個欄位的物件。
- 證物：轉換前後各跑一次盤點腳本，輸出寫到 change 目錄下 measure 資料夾的 `notation-before.json` 與 `notation-after.json`；瀏覽器驗證結果寫到同一資料夾的 `render-verification.jsonl`。

**Failure modes**

- 守門測試失敗時列出**所有**違規處，不是第一個就停。逐頁修的人需要完整清單。
- 盤點腳本遇到沒有 frontmatter 的 md 檔時，把整份內容當內文處理，不靜默跳過。
- 瀏覽器驗證若連不上 dev server，回報連線失敗本身，不得回報成「頁面沒有公式」。這是 counting-trio 那次踩過的坑：設定錯誤被報成內容壞掉。

**Acceptance criteria**

1. `pnpm test` 通過，且 `scripts/latex-notation.test.ts` 確實在其中執行。
2. 守門測試有負向控制：暫時把任一題的一個 `$\le$` 改回 `≤`，測試必須失敗且訊息指名該題；恢復後通過。這一步的執行結果記進證物。
3. 轉換後的盤點輸出 `pending` 為 0，`converted` 為 56（53 + 已完成的 3），`clean` 為 15。
4. `git diff` 顯示 53 個題目頁的改動全部落在 frontmatter 結束標記之後；frontmatter 區段零改動。
5. 瀏覽器驗證：抽樣頁面的 `mjx-container` 數量大於 0，內文沒有外洩的 LaTeX 原始碼（`\le`、`\times`、`^{` 等字串不出現在 `innerText`），且行內公式段落高度符合單行。
6. `Usage.md` 含記號分類表，且表中每一列的實例都能在實際題目頁找到對應。

**Scope boundaries**

- 在範圍內：`docs/challenge/*.md` 的 frontmatter 之後內文、`Usage.md`、新增的守門測試與盤點腳本、`vitepress-math-support` 與 `challenge-math-notation` 兩份 spec。
- 不在範圍內：任何 frontmatter 欄位、`docs/tutor/` 底下的檔案、`.vitepress/theme/custom.css`（`29e381c` 已改完，本 change 只補 spec 與驗證）、`prose` 的反引號問題、測資池與 WASM 建置。

## Risks / Trade-offs

- **53 頁手動轉換，機械替換會出錯** → 不做全域 `sed`。逐批轉換，每批結束跑盤點腳本比對剩餘數量，數字對不上就停下來查。盤點腳本本身在轉換前先跑一次留底，才有得比。
- **散文變數字母入 LaTeX 會讓 diff 變大，審查疲勞** → 分四批 commit，高密度批次獨立成 commit，讓 reviewer 一次只看一種難度。
- **A 級黑名單連反引號內都禁，可能誤殺未來合法的 Python 片段** → 提供 `latex-lint-ignore-next-line` 逃生門，且逃生門在 diff 中可見。目前全站 7 個含比較運算子的 code span 全部是誤包的約束，零誤殺。
- **`29e381c` 的 CSS 修正若被 Tailwind 升級推翻，53 頁一起壞** → spec 補上要求，瀏覽器驗證量段落高度。缺點是這項驗證不在 CI（jsdom 不做版面計算），仍需人工在部署前跑一次。這個缺口明列在此，不假裝已覆蓋。
- **本 change 的分支必須疊在 `fix/challenge-wording` 之上** → 若誤從 `staging` 開分支，CSS 修正不在，53 頁全部斷行且驗證會全綠（因為驗證跑在有修正的環境）。第一項任務就是確認分支基底含 `29e381c`。
- **`movie-ticket.md` 同頁混用貨幣與數學錢字號** → 全部 escape，並由守門測試持續擋。殘餘風險是未來有人在別頁寫價格忘了 escape，這正是守門要抓的。
