# 判題斷崖驗證數據（tasks 5.1／5.2）

實測日：2026-08-06（audit R1 修訂：正解量測對象改為**出貨 reference_solution 逐字碼**，非設計期精簡探針體——兩者相差 ~1.4×，肇因於多行迴圈體 vs 分號單行體的 line-event 差）。方法：settrace 全事件計數器（與 worker 同款語義）；牆鐘為本機 CPython 3.13.11 native 值，換算 Pyodide 一律乘保守係數 2（實務多為 2~4）。角落法：AC 側門檻取「該 band 最貴角落」、TLE 側取「最省角落」。op 上限 10M；正解門檻 ≤2.5M（上限/4，R1 裁決由上限/5 修正）；總預算硬殺＝6s×20 筆＝120s。generator 僅於建置期執行、不經判題 op counter，故不設 op 門檻。

## 5.2 繞道獵殺（design D6 清單逐條）

| 繞道 | 量測 | 死法 | 結果 |
|------|------|------|------|
| 568 逐查詢 math.factorial＋一次除尾零 | 單查詢 n=150000：0.44s／n=200000：0.69s native → 壓力最省角落 t=400×0.44×2 ＝ **354s**（單筆測資即超） | 總預算硬殺（≥2.95× 預算） | PASS |
| 10212 大數連乘＋逐位剝零 | 最省角落 m=80000、n=10⁸：連乘 4.8s＋剝零 11.9s native；單筆 t=2 ×2 係數＝67s；**壓力 6 筆累計 ≥402s** | 總預算硬殺（累計 ≥3.35× 預算；預算為跨筆總額，於第 2~3 筆壓力測資內死亡） | PASS（累計語義） |
| 10212 大數連乘後 str().rstrip('0') | m=80000 乘積 639,987 位 ≫ 4300 | int_max_str_digits=4300 → ValueError（RE） | PASS |
| 10212 math.factorial(N)//math.factorial(N−M) | N ≥ 10⁸：10⁸! 位數 ~7.6×10⁸（≥GB 級記憶體） | 記憶體災難／worker 崩潰或總預算硬殺 | PASS（構造性論證，未實測執行） |

備註：10212 繞道之「單筆 ≥240s」不成立（67s），獵殺依賴**跨筆累計**——總預算本身即跨筆總額，故累計語義即為硬殺的實際運作方式；若未來 useExecutor 預算公式改為單筆制，需重驗此條（design Risks 已載明）。
